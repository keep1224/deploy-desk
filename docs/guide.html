1快速上手

Deploy Desk 装在你自己电脑上，通过 SSH 操作服务器——服务器不装常驻管理程序，也不对公网开放管理端口。

1连接服务器配置页填 SSH 信息
2填项目表一行一个项目
3应用更改服务器按清单初始化
4发布后端 push · 前端传 dist

项目页顶部的四步条就按这个顺序打勾，走到全绿，整套流程就通了。

1

连接服务器

打开 配置 → 连接配置，按下表填写，点 保存，再点「服务器状态」里的 测试连接。左下角圆点变绿就是连通了。

字段怎么填
名称随便起，比如「生产服务器」
主机服务器 IP 或域名
端口SSH 端口，默认 22——不是网站端口
用户建议 root：部署脚本要写 /opt、/etc/nginx，还要执行 systemctl
认证私钥（填路径，有口令再填）或密码（输入后保存）

连不上？先确认端口是 SSH 端口，再确认密码/私钥有效、防火墙或安全组已放行。密码和口令只存在本机、用系统凭据加密，服务器和清单里都没有明文。

建议再点一次 采集状态（只读）：Node 20+、pnpm、Nginx、MySQL 是否齐全，内存、swap、监听端口都会列出来；缺什么会直接提示。

2

填项目表，应用更改

切到 项目，点表格上方的「+ 新增项目」，会在表尾追加一行，直接在单元格里填。最少只需名称和类型——域名不用管，前端行的站点地址默认就是当前连接的主机 IP（状态列那行小字，点开可改）。

填完点右上角 应用更改。第一次会弹窗确认，然后上传内置部署脚本和清单到 /opt/deploy，执行 apply.sh：

  • 后端：系统用户、/opt/apps/<项目>、裸仓库 /opt/git/<项目>.git、systemd 服务 nest-<项目>、.env；「建库」为自动时还会创建 MySQL 库和账号。
  • 前端：/var/www/<项目> 和 nginx 站点 deploy-<项目>.conf。

重复应用不会覆盖已有的 .env 和数据库。换电脑或重装面板时，如果服务器上已经有清单，在项目页空状态点「从服务器下载配置」，不用重建。

3

发布第一个项目

在项目表点对应行的「发布」：后端走 git push，前端上传 dist/。后端第一次需要一个 git 远端，弹窗会直接把命令写给你。详细步骤见 4 发布。

3项目清单

一行就是一个项目。表格里直接改，没有保存按钮；改动还没同步到服务器时，页面顶部会显示未应用。

列含义
项目名称同时用作目录名、系统用户、服务名和库名（- 换成 _）。3–31 位，小写字母开头，只能含小写字母、数字和 -
类型web 静态前端，由 nginx 提供服务；api Node 后端，跑 systemd 服务
端口api：后端自己监听的端口，留空从 3001 起自动分配，只绑 127.0.0.1；web：nginx 对外的 listen 端口，留空就是 80。整张表的端口不能重复
状态见下方状态表；api 行的小字显示表数、大小或缺库；web 行的小字是站点地址（nginx server_name），点它就能改——不填就用当前连接的主机 IP
建库仅 api：自动建库（库名=项目名），不建库用于纯接口项目；web 恒为 —
上游 api仅 web：选一个后端后，/api/ 会反代到它；不反代就选「不反代」
操作web 行有「复制」（站点地址，含端口）；每行有「发布」（发布代码，不含数据库）；api 行另有「数据库」组：迁移 / 备份 / 导入 SQL，只操作数据库；行尾 ✕ 移除

状态怎么读

状态含义怎么办
待初始化后端还没在服务器上创建点「应用更改」
未发布前端站点目录还没建点「应用更改」，再发布 dist
空目录前端目录建了，但里面没有文件点该行「发布」上传 dist
已部署 / 已发布正常—
未监听api 的端口没在监听，服务可能没起来查服务日志，核对端口后重新应用
缺库 库名数据库还没建出来点「应用更改」；核对「建库」列
配置有误名称、端口、域名或上游有问题，整行标红悬停看原因，改完再应用
未知还没读到服务器状态点「刷新状态」

配置有误时「应用更改」会被拦下。刚发布完状态没变化，点一下「刷新状态」。

一台服务器放多个前端

服务器只有 IP 时什么都不用填：每个前端行的站点地址自动取连接的主机，只要给每行写不同的显式端口（如 8080、8081），nginx 按 listen 端口区分站点；「复制」会自动带上端口。真有域名时，点状态列那行小字填进去即可。同一份清单换台服务器也不用改：地址里写的是纯 IP 时，切到哪个连接就跟着变成哪台机器的 IP；填的是真域名则保持原样。

移除项目

点行尾 ✕ 先从清单移除。如果服务器上已经有这个项目，会再问一次是否连 systemd 服务、/opt/apps、裸仓库和网站目录一起删除；后端还会单独确认数据库（不可恢复，建议先「备份」）。取消就只删清单，服务器保持原样。nginx 站点要等下一次「应用更改」才下线。

4发布

api后端项目

把代码推到服务器裸仓库，由钩子负责构建和重启。

本地仓库→git push→钩子构建→重启服务
web前端项目

把本地构建产物传上去，面板顺便做一次站点自检。

dist/→SFTP→/var/www/<项目>→HTTP 200

后端（api）

  1. 先在本地提交代码。服务器部署的是仓库里的提交，不是工作区。
  2. 点后端行的「发布」，选仓库目录。远端和分支是从这个仓库真实读出的下拉，默认选中指向该项目裸仓库的远端和服务器实际部署的分支；仓库目录按项目记住。
  3. 仓库还没有远端时不用开终端：点「git push 发布」会按选中的项目自动添加 deploy 远端（ssh://…/opt/git/<项目>.git）。面板还会把自带的部署公钥装到服务器，必要时自动打开 sshd 的公钥登录，首次推送多花一两秒。
  4. 服务器钩子依次执行 install →（有 build 脚本才构建）→ migrate → restart → 健康检查（/api/health）。

push 成功 ≠ 发布成功。钩子构建失败不会让 git push 失败。弹窗关闭后看「执行过程」里的 remote: 输出，那才是服务器端的构建日志；构建或迁移失败时，服务会继续跑上一个版本。

如果弹窗提示远端不是这个项目的裸仓库，或分支不是服务器部署的分支，推了也不会部署——先按提示改远端或分支。

前端（web）

  1. 本地构建出 dist/，确认里面有 index.html。
  2. 点前端行的「发布」→ 选 dist 目录。「发布到」已选中本行，文件会传到 /var/www/<项目>（和 nginx 的 root 一致）。
  3. 「上传前清空目标目录」默认勾选：先传 .staging，传完原子切换，上传期间旧站点仍可访问。不勾选则只覆盖同名文件，旧文件可能残留。
  4. 端口列写了显式端口时，上传后面板会在服务器本机请求站点，返回 200 才算通过；否则日志标红，先核对端口列，改过清单记得再「应用更改」。

前端发布前必须「应用更改」过：nginx 站点是按清单生成的，没应用就没有这个站点。

发布完看哪里

「执行过程」在页面顶部，是所有命令、上传进度和服务器输出的唯一入口：默认展开，点「关闭」收起，右下角「执行过程」按钮可以重新打开；蓝点表示有新输出，红点表示出过错。发布成功后项目表会自动刷新，后端变「已部署」，前端变「已发布」。

5数据库与 nginx

数据库

只对已部署的后端行可用，按钮灰说明还没部署。操作列里带「数据库」标签的一组按钮只管数据库，和上方的「发布」互不影响。连接信息来自该项目的 /opt/apps/<项目>/.env 里的 DATABASE_URL，面板不单独保存数据库密码。

按钮做什么说明
迁移pnpm exec prisma migrate deploy以项目用户在应用目录执行，生成/更新表结构
备份mysqldump ... | gzip存到服务器 /var/backups/<项目>-时间.sql.gz
导入 SQLmysql ... < 文件选本地 .sql / .sql.gz，先传到 /tmp 再导入，导入前二次确认

导入会覆盖同名表。拿不准先点「备份」，备份文件在服务器的 /var/backups。

「建库」列选自动建库会在应用更改时建库（库名 = 项目名把 - 换成 _），已存在的库和数据不会动；选不建库则写 DATABASE_ENABLED=false，适合纯接口项目或自己连外部库。改完点「应用更改」生效。

nginx

配置页底部的「服务器 nginx 配置」→ 查看：先跑 nginx -t，再只读展示 /etc/nginx/conf.d/deploy-<项目>.conf（每个项目一个）。这些文件每次「应用更改」都会整体重写，不要手改。

要加缓存头、gzip、额外的 location，写到服务器上的这个文件里：

/opt/deploy/snippets/<项目名>.conf

它会被 include 进该项目的 server { } 末尾，apply 永远不会覆盖它。写完点一次「应用更改」。片段语法错误会让 nginx -t 失败，此时 apply 会回滚本次 nginx 改动，站点保持原样。想完全自己接管，就在 /etc/nginx/conf.d/ 另建一个不以 deploy- 开头的配置文件。

6常见问题

测试连接失败，或提示「密码未保存」

先确认认证方式选的是「密码」还是「私钥」。密码方式要重新输入一次并点保存；私钥方式要确认本机存在该文件、口令正确。端口要填 SSH 端口。

应用更改报「内置部署脚本缺失」

安装包不完整：resources/server 下应有 apply.sh、add-project.sh、post-receive、db.sh、remove-project.sh 五个文件。重新下载安装包即可。

nginx 显示「通过，有告警」或 suspicious symbols

多半是站点地址写成了 http://example.com 这类带路径的值。nginx 的 server_name 只认主机名，点状态列那行小字改成 example.com 再「应用更改」。

前端发布成功，打开还是旧页面 / 404

看日志里的「站点自检」：文件已到位但 nginx 没返回 200，通常是端口列不对或清单没应用。确认上传的是 dist 里的内容（含 index.html），必要时勾选「上传前清空目标目录」重传，再刷新浏览器缓存。

后端发布后 502 / 健康检查超时

看「执行过程」里的 remote: 停在哪一步，常见是 install、build、migrate 失败或端口被占。服务器上可执行 systemctl status nest-<项目> 和 journalctl -u nest-<项目> -n 50 查看。健康检查请求 /api/health，项目没有这个路由会超时（此时服务可能已在运行）。

「迁移 / 备份 / 导入」是灰的

这些按钮只对已部署的后端开放。先完成「应用更改」并成功发布一次，再点「刷新状态」。

换电脑或重装系统后密码没了

密码用当前系统账户加密，换机器后无法解密，重新输入保存一次即可。服务器上已有的清单可以在项目页点「从服务器下载配置」取回。

7安全与限制

  • 面板只在本机运行，不监听公网端口；服务器上不装常驻管理服务。
  • 密码/私钥口令用系统凭据加密（Windows DPAPI、macOS 钥匙串），明文不出主进程；私钥只保存路径。
  • 每个后端用独立系统用户运行，.env 权限 600；MySQL 只监听本机。
  • 2G 内存的服务器默认给每个后端 MemoryMax=384M、运行堆 256M，建议后端数量控制在 2–3 个并开启 swap。
  • 「应用更改」会以 root 身份在服务器执行脚本，只在改完清单后点；建议服务器只允许密钥登录。
